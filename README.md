# 赛博囚笼：猎场协议

本地 2D 俯视生存模拟：8 名逃亡者对抗 1 名无敌猎人。设施连续缩圈；最后一名仍存活的逃亡者立即获胜，全员淘汰则猎人获胜。模拟使用固定 100ms 步长，同一地图种子、推理种子和模型版本可复现。

## 一键启动游戏（Windows）

双击仓库根目录的 `START-HUNTER.cmd`。首次运行会自动执行 `npm install`。看到绿色地址 `http://127.0.0.1:5175/?seed=1701` 后，浏览器会自动打开。

游戏期间请保留启动窗口。要停止服务器，回到该窗口按 Enter。普通启动器只运行网页，**绝不会启动训练**。若启动失败，窗口会保留错误；常见原因是 5175 端口已被占用，或首次安装依赖时网络不可用。

终端启动：

```powershell
cd apps\hunter-arena
npm.cmd install
npm.cmd run dev -- --port 5175 --strictPort
```

## 策略选择

- **固定回退策略**：默认、安全、无需模型文件；按观测与奖励特征实时决策。
- **Current（本机验收模型）**：训练启动器完成训练和 200 局技术验收后放入 `public/models/current`。文件不存在时网页会明确显示不可用。
- **Smoke（管线测试用）**：仓库附带的小步数模型，只证明 Python→JSON→浏览器推理管线可用，不代表训练质量或平衡性。

策略在开局时冻结，比赛中不能更换。因此固定种子不会因异步加载模型而中途改变。

## 真正的 PPO 训练

双击 `apps\hunter-arena\training\训练模型.cmd`。它会：

1. 创建 `training\.venv` 并安装 `pyproject.toml` 中锁定的依赖；
2. 交替训练逃亡者与猎人（默认每方 250,000 步）；
3. 对固定种子 `1..200` 做两遍确定性评估；
4. 只有模型版本与 SHA-256 精确匹配、种子完整且唯一、两遍结果一致、每局结果结构有效、超时率不高于 20% 时，才以目录级原子替换发布到 `public/models/current`。

训练主要消耗 CPU 和内存，首次安装需要网络。训练可能持续数小时；可以关闭网页，但不要关闭训练窗口。失败的候选不会覆盖 Current。再次运行会从完整世代检查点继续。Smoke 模型不能视为已经通过平衡验收。

## 操作和录制

- 空格：开始、暂停或继续
- H：隐藏或显示 HUD
- Esc：退出 OBS 模式
- 1× / 2× / 4×：改变播放速度，不改变固定步长模拟逻辑
- 自动导演 / 全景：切换观战镜头
- 同种子重放 / 新地图：复现当前设施或换种子
- OBS：隐藏控制和 HUD；建议用 OBS“窗口捕获”，画布 1920×1080，浏览器硬件加速保持开启

1280×720 和 1920×1080 都在自动测试范围内。集成显卡可使用全景与 1×；训练使用 CPU，不需要独立显卡。

## 回放 V2

比赛结束后点“导出回放”下载 JSON；点“导入回放”选择文件，校验通过后可以播放或拖动时间轴。`SurvivalReplayV2` 保存地图/推理种子、开局冻结的双方策略版本、逐 tick 已解析动作、赛果、奖励摘要和最终姿态。导入会深度校验所有数值、动作、tick、策略、赛果和角色字段，并完整重演来核对最终赛果与姿态。指定模型缺失会明确标记为 fallback-driven，但回放仍使用已经记录的确定动作。V1 是旧终端玩法格式，会显示中文“不兼容”错误。

# 自动追逃基线与追逃 V2

双击项目根目录 `START-AUTO-BASELINE.cmd` 打开代码控制的自动追逃；默认示例为地图 01、种子 1。网页路径为 `/?mode=pursuit&map=01&seed=1`。可换图池 01–10、种子和猎人速度，默认速度为逃亡者的 1.35 倍。

新比赛默认最多 200 秒（2000 tick）。剩余一人立即结算；超时则如实显示未捕获完，不预设胜者。OBS 按钮隐藏操作界面，Esc 返回。网页明确标注代码基线，不冒充训练模型。

猎人每秒感知 40 格内无遮挡角色，最多主动切换两次目标后锁定；捕获或连续五秒跟丢后重新选择。已知地图只用于路径规划，不提供墙后实时角色位置。逃亡者仅根据自身看到或短时记住的猎人逃跑。

训练工作台可另选 `追逃 V2：40格感知＋路线提示（PPO）`。该模式由 PPO 决定猎人移动，复用同一感知与路线规则，观测为 schema 2 / 325 维；旧 313 维模型不能直接加载到新协议。未自动启动长训。既有实验保留原时长与源码快照，新建任务默认 200 秒。

200 秒版节奏参数：初始位置距猎人的可通行路程为 8–35 格；开局后可自由走遍地图。逃亡者采用 12 格短程逃跑规划，视线发现猎人后每秒重新规划，猎人利用最近观测的移动方向作短时搜索预测。参数统一适用于全部地图和种子，不按单局调整结果。

2026-10-25 批量实测：种子 1–10 平均捕获 6.9 人；独立种子 101–150 平均 6.66 人，35/50 局在 200 秒内捕获七人。该结果属于代码自动寻路基线，不代表 PPO 模型已达到相同性能。原始数据见 `artifacts/pursuit-benchmark*.json`。

## 新玩法：气运之子 · 两阶段恶魔追逃

双击项目根目录 **`START-DEMON-ARENA.cmd`**，或在已运行的本地服务打开 `http://127.0.0.1:5175/?mode=demon&map=01&seed=1`。这是可重复运行的代码策略游戏，不需要启动训练。启动脚本可以复用带有本应用标记的已有服务器；关闭网页后仍可重新打开。自行启动时执行：

```powershell
cd apps\hunter-arena
npm.cmd run dev -- --port 5175 --strictPort
```

- 八颗编号小球从共同入口入场，15秒内选择房间并搜取道具；保护期间恶魔尚未激活。
- 第一轮恶魔追捕最多100秒，剩4人或更少即进入集合动画；时间到仍有更多人，则全部真实幸存者换图。
- 换图动画不占比赛有效时间。第二张地图重新入场并保护10秒，刷新房间物资；总有效时间最多250秒。
- 只剩一人立即显示“本场气运之子”。实际同一时刻全部被捕则无人幸存；超时多人则展示真实名单，不指定冠军。
- 白色研究设施、暗红恶魔、彩色编号小球；被捕球变灰留在原地图，换图后不复制旧尸体。第一层至少8个、第二层至少4个可用房间，复用图池布局并保留连通区域。
- 房间随机提供冲刺、诱饵信标、穿墙符或封门器。每人最多持有一个、用完消耗；未使用道具可带入第二层，搜到新物资会替换旧道具。
- 恶魔默认1.35倍速度，仍受墙体遮挡；诱饵需在20格无遮挡范围被实际感知。恶魔无敌、门只暂时阻拦。最后40秒开始预告并尝试封闭安全可封的外围区域，不通过毒圈强行淘汰。

空格开始/暂停，H隐藏界面，Esc退出录制。全景/自动镜头、1/2/4倍速、重新比赛、新种子、全屏和OBS模式位于底部控制区。右上角“监控设置”提供比赛配置、总音量、环境/事件/追逐三路音量、静音、音效试听和氛围动画开关；开始比赛后设置自动收起。音效在点击开始或试听后启用，全部本地合成，无需下载素材。OBS建议1920×1080窗口捕获，添加桌面音频；换图动画与声音会一并录入。

`map=01`指定第一张地图（01–10）；第二张不同的地图、房间物资与策略偏好由种子确定。同一地图、种子和速度可复现比赛；不同播放倍速只改变观看速度。旧基线可从页面链接返回，训练数据与模型不变。

开发验证与批量统计：

```powershell
npm.cmd test
npm.cmd exec -- vitest run scripts/demon-benchmark.test.ts scripts/launchers.test.ts
npm.cmd run build
npm.cmd run test:e2e
npm.cmd exec -- tsx scripts/demon-benchmark.ts 200 0 artifacts/demon-benchmark-200.json
```

统计包括第一轮4人目标达成率、唯一幸存/超时情况、各编号胜率、道具使用及5秒后仍活着且距恶魔超过8格的比例。换图打断的道具随访不作成功计数，这些比例用于诊断，不等同于道具造成的因果收益。原始报告属于代码控制器表现，与PPO模型质量无关。

## 白色废弃研究所视听版（2026-10-27）

沿用同一比赛规则，画面改为旧白地砖、裂纹、水痕、褪色房号、门框与警示灯，配柔和球面高光、道具徽标、死亡褪色和恶魔表现。静态材质离屏缓存，装饰使用独立坐标哈希，不消耗比赛随机数。若不需要灯光/浮动等氛围动画，可在设置中关闭；减少动态效果的系统偏好也会生效。

声音包括降临低鸣、捕获熄灭、四种道具、换图金属门、最后两人心跳与终局音。环境和追逐声可调低，便于后期配旁白。设置中的“试听音效”不启动比赛，也不改变赛果。试听合辑保存为 `artifacts/lab-sound-preview.wav`，完全来自本地合成器输出，没有录制麦克风或其它应用。

`artifacts/lab-presentation-parity.json`核对规则源哈希及11个固定种子的完整状态签名（含原来的超时种子）；旧200局平衡报告仍为规则基线，本次没有重新调参或将旧数据冒充新增200局测试。实际帧间隔测量和声音信号检查分别在`lab-frame-times.json`与`lab-audio-check.json`。
